Remote-server design — mockup pass

Per the four decisions: connection is a project-level property; folder discovery shown as both Variant A (text path + Validate) and Variant B (mini tree browser); new projects default to Local; onboarding collapses to two steps (Environment → First project). The Connection step becomes inline at project creation.

All screens are dark theme to match mockup.html / mockup-onboarding.html. Static HTML, no JS interactions wired up — this is a visual pass to react to.

Why collapse: The 3-step flow forced every first user to make a hosting decision before they'd seen the app. With connection at the project level, Local is the only sensible default for first-launch; remote profiles get created on-demand when the user is actually ready (i.e. clicks Remote SSH in AddProjectDialog). Step 2 (First project) reuses the same AddProjectDialog from sections 1-3, so the user discovers the connection picker there.
